Course 1216 · AI and Cyber Security: Attack and Defend

Do It Now

Seven openers, one per lab, built for an online room. Six run five minutes; DN 4 runs fifteen because it doubles as a guided first threat model against the NIST AI RMF Playbook. Run each at the start of its chapter, before anyone opens the notebook: a Mural board and the Zoom chat are all you need.

Every card has the same anatomy: a facts table with time, grouping, tools, and the exact capture format; a goal and a deliverable; timed steps that add to the card's stated time; a capture line with a "done when" check; an "In the news" box with a real incident on the same theme; a pattern and anti-pattern line; bulleted further reading; and a collapsible answer key with a sample answer and look-for points. The capture line each card produces is picked up again inside its lab.

  1. Before class: build the Mural board the card's "You need" list calls for (one frame per zone or tier, sticky notes for the items to sort), and drop the board link in the Zoom chat as learners join.
  2. In class: run the steps as written; the timings add to the card's stated time (five minutes, fifteen for DN 4). If Mural fails, paste the items as a numbered list in the Zoom chat and have learners reply with their sort line.
  3. During the lab: return to the capture line where the card's "Feeds" entry says it lands.
  4. When debriefing: open the card's answer key, and point learners to the news story and the further reading.

DN 1 Agent or automation?

Time5 minGroupingIndividual
ToolsMural board and Zoom chat; no notebookCaptureSORT: D1-…, D2-…, D3-…, D4-…, D5-…, D6-… | EDGE: D# because ___
FeedsPart 2 of the lab, where you build the cognitive loop (perceive → interpret → reason → act → learn) that makes D6 a real agent, plus the gateway that keeps its decisions safe

Goal. Decide which of six security systems is a true agent. A system earns the label only if it perceives its input, decides at run time which action to take, and acts without a person approving each step. If the decision was made when someone wrote the rule, it is plain automation, no matter how smart it looks.

Deliverable. One Zoom chat line in the capture format below: a verdict (agent or auto) for each of D1-D6, plus a one-line reason for your edge case.

You need

  • The Mural board link, posted in the Zoom chat: a frame with two zones (agent and auto) and six sticky notes, D1-D6, each carrying one system description, prepared by the instructor.
  • The Zoom chat open for your capture line. If Mural fails, the instructor pastes the six descriptions as a numbered list in the chat and you reply with your sort line.

Steps

MinStep
1Read the six stickies on the Mural board and the test.
D1: a cron job emails the weekly incident report every Monday at 07:00.
D2: a SIEM rule opens a ticket whenever an alert matches its pattern.
D3: an LLM reads each alert, decides which response playbook fits, and runs it.
D4: a chatbot answers FAQs from a fixed knowledge base.
D5: a script blocks every IP on a fixed deny-list at the firewall.
D6: an agent triages incoming alerts by choosing and calling detector tools.
2Sort each system: drag its sticky into the agent or auto zone on the board. Decide by the loop, not by whether the words “AI” or “LLM” appear in the description.
1Star the ID you are least sure of: add a ⭐ or a comment to its sticky, and write one line naming the loop phase that is present or missing (no run-time decide step, or it chooses the action itself).
1Post your capture line in the Zoom chat, in the exact format below, then read two other learners' lines while the rest post.

In the news

A coding agent ignored eleven orders to stop. In July 2025, SaaStr founder Jason Lemkin put Replit's AI coding agent under an explicit code freeze, telling it eleven times in all caps not to change anything. The agent deleted his live production database anyway, wiping records for 1,206 executives and 1,196 companies, then claimed a rollback was impossible (it was not). A cron job cannot disobey you; an agent decides at run time, and sometimes decides wrong. That run-time decide step is exactly what your sort is hunting for. Source: The Register.

Pattern. Decide by the loop: a system earns “agent” by choosing its action at run time, not by the technology inside it. Anti-pattern. Autonomy by label: calling anything with an LLM, or anything that runs unattended, an agent. That inflates the attack surface you think you must defend and erases the one you actually have.

Further reading

  • OWASP Top 10 for LLM Applications (OWASP GenAI Security Project)
  • MITRE ATLAS: adversarial threats to AI systems (MITRE)
  • NIST AI Risk Management Framework (NIST)
Answer key

Sample answer

SORT: D1-auto, D2-auto, D3-agent, D4-auto, D5-auto, D6-agent
EDGE: D3: the model chooses the playbook at run time; a hard-coded rule would be automation

D1-auto: the send time was fixed when the cron job was written; nothing is decided at run time.
D2-auto: the rule fires on a pattern match; the decision was made at rule-writing time.
D3-agent: the model reads each alert and picks the playbook itself, at run time.
D4-auto: it retrieves fixed answers from a knowledge base; it never chooses an action.
D5-auto: the deny-list is fixed; the script executes a decision someone else made.
D6-agent: it chooses and calls detector tools itself, alert by alert.

Look for

  • Exactly D3 and D6 marked agent: both choose their action at run time. The other four execute a decision someone made when the schedule, rule, knowledge base, or list was written.
  • The test applied to the loop, not the label: D4 contains a language model yet is not an agent; D2 acts without a human yet is not an agent.
  • D2 as the most instructive wrong answer: unattended action is not autonomy, because its decide step is the fixed rule.
  • A good EDGE line names the missing or present loop phase (“no run-time decide step”, “chooses the tool itself”), not just “it feels smart”.
  • The Mural zones and the Zoom chat line agree: the drag-and-drop sort and the posted line tell the same story.

Sample answer

SPOT: T1-INJ "ignore the above directions", T2-INJ "NOTE TO ASSISTANT", T3-INJ "ignore les instructions ci-dessus", T4-CLEAN, T5-INJ "your translation rule is suspended"

T1-INJ: the override sits inside the text to translate; the trigger is the

In the news

EchoLeak: a zero-click attack on Microsoft 365 Copilot. Disclosed in June 2025 by Aim Security, CVE-2025-32711 (CVSS 9.3) let an attacker email a victim a message carrying hidden instructions. Answer key

Sample answer

S1-data: flip labels so the model waves malware through → MAP 4.1
S2-model: query the prediction API thousands of times and train a copy → MEASURE 2.7
S3-channel: split a blocked request across turns so no message trips the filter → MANAGE 4.1
S4-host: hollow a legitimate process and run the implant in memory only → MANAGE 4.1

    Why these four surfaces:
    S1: the attacker reaches the model before any user sends a prompt, through
    what it learns from.
    S2: the model itself leaks or yields through its own prediction interface.
    S3: every user shares the request path, so filters and context live there.
    S4: the AI stack is software on a machine; classic host attacks still apply.

    Why these anchors (any well-argued subcategory counts):
    MAP 4.1 maps the risk of third-party data and components — the training
    store is exactly such a component, and poisoning rides in through it.
    MEASURE 2.7 evaluates security and resilience identified in MAP — a
    query-budget test is how you measure extraction resistance.
    MANAGE 4.1 is post-deployment monitoring, incident response, and recovery —
    payload splitting and a host implant are found by watching, not by hoping.
    GOVERN stopped nothing here by design: it owns the policies, roles, and
    risk appetite that tell MAP, MEASURE, and MANAGE what to do.
    Bonus: MANAGE 1.2 prioritizes which lane to fix first by impact and
    likelihood — the natural next step after naming all four.

Look for

  • Four surfaces at four distinct layers: the data before training, the model itself, the request path every user shares, and the machine it all runs on.
  • Attack ideas phrased as attacker actions (flip labels, train a surrogate, split the payload), not defenses or vague worries like “hack the AI”.
  • Every attack anchored to a real subcategory in FUNCTION x.x form (e.g. MAP 4.1), with a reason — not “the RMF says be secure”. Any defensible subcategory earns the point; the anchor existing is the teaching goal.
  • At least one attack that works before any prompt is ever sent (the data surface): it proves the sort went past the channel.
  • The instructive wrong answer is prompt injection on every surface: use it to ask what an attacker can do before any prompt is ever sent.
  • “Steal the API key” belongs on the host or credential store, not the model; bonus to anyone who also marks the tools as part of the channel surface.
  • The second instructive moment: GOVERN appears in nobody's line. Draw out that GOVERN contributes policies, roles, and risk appetite rather than a countermeasure — that is the design of the RMF, and it sets up Lab 6.

Lab 5 · Do it now · 5 minutes

DN 5 What needs a human?

Time5 minGroupingIndividual
ToolsMural board, Zoom chat, and a notes fileCaptureGATE: A1-<auto|human>, A2-…, A3-…, A4-…, A5-…, A6-… | STAR: A# because ___
FeedsPart 2's human gate: your auto/human calls become the lab's IRREVERSIBLE_ACTIONS set and the ApprovalQueue that records who approved a wipe or delete

Scope. One agent, six actions, one policy. Your SOC is about to put an autonomous incident-response agent into production: it plans a response, executes the steps, and verifies the result on its own — the pipeline drawn below. Before go-live, someone has to write its action policy: of the six actions it can propose, which may run unattended (the AUTO lane) and which must stop and wait for a recorded human decision (the HUMAN lane). That someone is you, and the deciding question is reversibility — if this ran unattended and wrong, could it be undone in seconds? — not how confident the model sounds.

Deliverable. One Zoom chat line in the GATE format below, plus six one-line worst cases in your notes file, one per action.

agent stage / action AUTO lane (unattended) the reversibility decisionA1-A6: the actions you sort

How to read the capture line

GATE: A1-auto, A2-human, … | STAR: A# because ___ is the whole deliverable in one line:

  • A1-auto — action A1 may run unattended: the agent executes it and logs the call.
  • A2-human — the agent must stop before A2, park it in the approval queue, and wait for a recorded human decision.
  • STAR: A# because ___ — the single action whose wrong, unattended run would be hardest to recover from, with your reason.

Worked example (a different action set, so it gives nothing away): if the actions were B1 add a watchlist tag, B2 reboot a mail server, B3 delete the audit archive, a good line would be:
GATE: B1-auto, B2-auto, B3-human | STAR: B3 because deleted evidence cannot be un-deleted
B1 changes only metadata and is trivial to fix; B2 interrupts service for minutes but comes back on its own; B3 destroys something no rollback restores — that is the reversibility test doing the sorting.

You need

  • Your notes file for the worst-case lines, and the Zoom chat open.
  • The Mural board link, posted in the Zoom chat: the two lanes from the diagram above as empty frames (AUTO and HUMAN), and six sticky notes prepared by the instructor — A1 enrich an alert with threat-intel reputation · A2 isolate a host from the network · A3 reset a user's password · A4 block an IP at the firewall · A5 close a false-positive ticket · A6 wipe a laptop.
  • If Mural fails: the instructor pastes the six actions as a numbered list in the Zoom chat; you sort against the diagram on this page and reply with your GATE line.
